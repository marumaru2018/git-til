## ️ React で使われる主なバリデーション方法

「HTML 標準 → RHF → Zod」の順で学習すると理解しやすい

**React におけるバリデーションは、大きく「フォーム入力チェック」と「型・スキーマによる検証」に分けられる。
代表的には、HTML 標準の制約、React Hook Form、Yup/Zod などのスキーマバリデーションライブラリがよく使われる。**

---

### 1. **HTML 標準のバリデーション**

- `required` 属性や `type="email"` などを利用
- ブラウザが自動でチェックしてくれるため簡単
- ただし、カスタマイズ性が低く、UI/UX に合わせた柔軟なエラーメッセージ表示が難しい

---

### 2. **React Hook Form (RHF)**

- 軽量でパフォーマンスに優れたフォーム管理ライブラリ
- `register` を使って各フィールドを管理し、`errors` オブジェクトでエラーを取得
- バリデーションルールを直接指定可能（例：`minLength`, `pattern`）
- Zod や Yup と組み合わせることで型安全なバリデーションが可能

---

### 3. **Yup / Zod などのスキーマバリデーション**

- **Yup**: 宣言的にスキーマを定義できるライブラリ。React Hook Form とよく組み合わせて使われる
- **Zod**: TypeScript との親和性が高く、型安全なバリデーションが可能
  - 例:
    ```ts
    const schema = z.object({
      email: z.string().email("正しいメールアドレスを入力してください"),
      password: z.string().min(6, "パスワードは6文字以上必要です"),
    });
    ```
- RHF の `zodResolver` を使うことで、フォーム送信時に自動的にスキーマチェック

---

### 4. **カスタムバリデーション**

- 独自の関数を定義して、条件に応じてエラーを返す
- 例: ユーザー名が既存データと重複していないかを API でチェック
- RHF の `validate` オプションや `setError` を利用して柔軟に対応可能

---

## まとめ

- **簡易チェック** → HTML 標準属性
- **柔軟なフォーム管理** → React Hook Form
- **型安全・複雑なルール** → Yup / Zod
- **特殊ケース対応** → カスタムバリデーション

React 開発では、**「RHF × Zod」** の組み合わせが現在もっとも主流で、型安全性・拡張性・開発効率のバランスが良い。

ZoD のインストール

```
npm install zod
```
