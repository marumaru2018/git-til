サイドチャネル攻撃の手法であるタイミング攻撃の対策

ゼロデイ攻撃
サーバの可用性を脅かす脆弱性が発見されてから対策が提供されるまでの間に、その脆弱性を攻撃者が悪用することによって、標的のサーバのリソースを枯渇させ,利用を妨害する。

SYN フラッド攻撃
最初の接続要求 (SYN) パケットを繰り返し送信することによって、標的のサーバの利用可能なメモリを枯渇させ、利用を妨害する。

DRDoS 攻撃（分散リフレクション DoS 攻撃）
攻撃者が直接ターゲットを攻撃するのではなく、インターネット上の多数のサーバ（DNS サーバなど）を「踏み台」にして攻撃する手法です。
送信元を偽って問い合わせると、その何倍にもなった応答がターゲットに殺到するため、効率的に大きなダメージを与えられます。

Slow HTTP DoS 攻撃
多数の HTTP リクエストを長期間掛けて送信し続けることによって、標的の Web サーバのセッションを占有し、利用を妨害する。

Smurf 攻撃
ICMP エコー要求パケットの送信元 IP アドレスに攻撃対象の IP アドレスを設定し、宛先にブロードキャストアドレスを設定して送信することによって攻撃対象を利用不能にさせる。
攻撃者は、ネットワーク全体に「返事して！」と呼びかける DDoS パケット（ICMP エコー要求）をブロードキャストで送ります。その際、「送り主」の IP アドレスを攻撃対象（被害者）のものに偽装します。ネットワーク内の全コンピュータが、偽装された送り主（＝被害者）に対して一斉に返事（ICMP エコー応答）を送るため、被害者の回線がパンクします。

DDoS 攻撃（メールボム）
ボットネットを使って多数の端末から攻撃対象のメールサーバに大量のなりすましメールを送信し、攻撃対象のメールサーバを停止させる。

リフレクタ攻撃に悪用されることの多いサービスの例
DNS, Memcached, NTP
リフレクタ攻撃（反射攻撃）は、小さなリクエストで大きなレスポンスが返ってくるサービスを悪用します。DNS（特に ANY リクエスト）、Memcached（キャッシュデータ）、NTP（時刻情報）は、いずれも公開されており、問い合わせに対して何倍もの大きさの応答を返す性質があるため、リフレクタ攻撃の踏み台として非常に悪用されやすいサービスです。

マルチベクトル型 DDoS 攻撃
Web サイトに対して, SYN Flood 攻撃と HTTP POST Flood 攻撃を同時に行う。
「マルチベクトル」とは「複数の手法を同時に使う」という意味です。

1. SYN Flood 攻撃: ネットワーク回線やファイアウォールを狙う攻撃（レイヤ 3/4）
2. HTTP POST Flood 攻撃: Web サーバの処理能力を狙う攻撃（レイヤ 7）
   このように、異なる層や種類の攻撃を同時に行うことで、防御側に対応を難しくさせるのがマルチベクトル型攻撃です。

PQC (Post-Quantum Cryptography)
量子コンピュータを使った攻撃に対しても従来のコンピュータを使って安全性を確保できる暗号技術
PQC は「量子コンピュータ"後"の暗号」という意味で、将来の量子コンピュータによる攻撃にも耐えられるように、現在のコンピュータで動くように設計された新しい暗号アルゴリズムのことです。

量子暗号の特徴
量子通信路を用いて安全に共有した乱数列を使い捨ての暗号鍵として用いることによって、原理的に第三者に解読されない秘匿通信が実現できる。
量子通信路 （専用の光ファイバーなど）を使い、量子力学の原理（観測すると状態が変わり、盗聴が必ずバレる）を利用して、安全に暗号鍵（使い捨ての暗号鍵 ）を共有します。これにより、原理的に解読されない 通信が可能とされています。

CRYPTREC 暗号リストには推奨候補暗号リストがあり、それは安全性及び実装性能が確認され、今後,電子政府推奨暗号リストに掲載される可能性がある暗号技術のリストである。
「推奨候補暗号リスト」は、安全性は確認されたものの、まだ実績が少ないため「推奨」の一歩手前、いわば「期待の新人」リストです。

CRYPTREC は、電子政府が安全な暗号を使うための「暗号技術の専門家チーム」のようなものです 。主な活動は、どの暗号技術が安全か技術的に検討し、世界で通用するか（国際競争力）や、どうすれば安全に使えるか（運用面）を検討することです 。

電子政府推奨暗号リストとは、CRYPTREC によって安全性及び実装性能が確認された暗号技術のうち、市場における利用実績が十分であるか今後の普及が見込まれると判断され、当該技術の利用を推奨するもののリストである。

ファイアウォールにおけるステートフルパケットインスペクションの特徴
過去に通過したリクエストパケットに対応付けられる戻りのパケットを通過させることができる。
ステートフルパケットインスペクションは、通信の「文脈」を記憶する賢いファイアウォールです。例えば、内部から外部への通信（行き）を許可した場合、その通信に対する返事（戻り）の通信も自動的に許可します。これにより、戻りの通信のためのルールを一つ一つ設定しなくて済むので、安全かつ効率的です。

ステートフルパケットインスペクション方式のファイアウォールの特徴
パケットフィルタリングを拡張した方式であり、過去に通過したパケットから通信セッションを認識し、受け付けたパケットを通信セッションの状態に照らし合わせて通過させるか遮断するかを判断する。
単純なパケットフィルタリング（住所とポート番号だけ見る）を拡張し、通信の**セッション（一連の会話）を記憶します。そして、その会話の状態（State）**に照らし合わせて、「これはさっきの通信の返事だから通して OK」といった判断を行います 。

ファイアウォールにおけるダイナミックパケットフィルタリングの特徴
過去に通過したリクエストパケットに対応付けられる戻りのパケットを通過させることができる。
これがステートフル（＝動的）であることの最大の特徴です。内部から外部への通信（リクエスト）を記憶しておくことで、その返事（戻り）のパケットが来たときに、「これはさっきのリクエストに対応するものだ」と動的に判断して通過させることができます 。

SHA-512/256 の説明
入力データに SHA-512 に基づいたハッシュ関数を 1 回適用し,512 ビットの値を 出力した後,256 ピットに切り詰めて出力する。
SHA-512/256 という表記は、「ベースの計算方法は SHA-512 を使いますが、最終的に出来上がるハッシュ値（512 ビット）のうち、先頭の 256 ビットだけを切り詰めて（短くして）使います」という意味です 。SHA-512 の安全性（計算の複雑さ）を持ちながら、出力サイズを SHA-256 と同じ 256 ビットにしたい場合などに使われます。

ハッシュ関数の性質の一つである衝突発見困難性
衝突発見困難性とは、ハッシュ値が一致する二つの元のメッセージの発見に要する計算量が大きいことによる、発見の困難性のことである。
衝突発見困難性とは、「異なるデータなのに、ハッシュ値が偶然同じになってしまう（衝突する）ペアを見つけるのが非常に難しい」という性質のことです。良いハッシュ関数は、この衝突が起きにくいように設計されています。
